# 생기부 스킬 사용 가이드

설치를 마친 뒤 실제로 초안을 받아 나이스에 넣기까지의 순서를 적은 안내서입니다. 설치 방법은 README의 '설치'를 보십시오.

## 한눈에 보기

```
준비(성취기준 · 관찰 메모 · 학생 기호) → 스킬 부르기 → AI 질문에 답하기
→ 초안 받기(AI 문체 점검 · 기계 검사까지 끝난 것) → 교사 확인 목록 점검 → 나이스 입력
```

AI가 하는 일은 초안까지입니다. 사실 확인과 최종 입력은 교사가 합니다.

## 1. 시작하기 전에

### 꼭 켜 둘 것

| 설정 | 왜 |
|---|---|
| 코드 실행(Claude 앱의 기능 설정 · 코딩 에이전트는 기본) | Byte 계산, 금칙어 검사, AI 문체 점검 게이트가 이것으로 돕니다. 꺼져 있으면 분량이 '추정'으로 나오고 검사를 손으로 대신합니다 |
| 추론 수준 **높음**(모델 설정에서 고를 수 있으면) | 시험에서 낮음 · 중간은 고치는 도중 사실 낱말(예: '알고리즘의 효율성')을 지운 일이 있었고 높음은 모두 지켰습니다. 비용 차이는 10% 안팎입니다 |
| 대화 내용 학습 사용 끄기(서비스에 옵션이 있으면) | 학생 관련 내용이 모델 학습에 쓰이지 않게 합니다 |

### 준비물

1. **성취기준 원문**(세특일 때). `0. 내 교과 정보 (교사가 채움).md`에 이번 학기 성취기준을 교육과정 원문 그대로 붙여 두면 매번 묻지 않습니다. AI는 성취기준을 지어내지 않으므로, 없으면 원문을 달라고 합니다.
2. **관찰 메모**. `4. 교사 입력 양식.md`의 양식(A 세특 · B 창체 · C 자유학기 · D 행특 · E 여러 학생)을 채워 붙이면 질문이 줄어듭니다. 문장으로 다듬을 필요는 없습니다. 이런 것이 있으면 좋습니다.
   - 학생이 고른 주제 · 방법
   - 막힌 지점과 넘은 방법
   - 그렇게 판단한 장면(예: '성실했다' 대신 '세 번 다시 재어 평균을 냈다')
   - 모둠에서 맡은 역할, 학기 초와 달라진 점
3. **목표 분량(Byte)**. 숫자만 말하면 Byte, '자'를 붙이면 글자 수×3으로 계산합니다. 말하지 않으면 세특 · 창체 · 자유학기 1,500Byte, 행특 900Byte로 씁니다.

### 개인정보 — 넣기 전에 한 번 더

- 학생은 '학생1', '학생2' 같은 **임시 기호**로만 씁니다. 대응표는 교사만 보관합니다.
- 실명, 학번, 생년월일, 가족 사항, 질병 · 건강, 상담, 학교폭력 관련 내용은 넣지 않습니다.
- 날짜가 붙은 사건, 신체 특징, 다른 학생 이름도 학생을 알아보게 하는 단서라 뺍니다.
- AI가 이런 정보를 발견하면 멈추고 알려 줍니다. 그때는 기호로 바꿔 다시 넣으시면 됩니다.

## 2. 스킬 부르기

| 쓰는 곳 | 부르는 법 |
|---|---|
| Claude Code(플러그인 설치) | `/생기부` 뒤에 요청을 씁니다 |
| Claude 앱 · Gemini 앱(zip 업로드) · 다른 코딩 에이전트 | 말로 부릅니다. "생기부 써줘", "세특 초안 써줘", "행특 써줘", "동아리 특기사항" 등 |
| ChatGPT 등(지침 붙여 넣기) | 프로젝트에서 그냥 요청합니다. 지침이 이미 들어가 있습니다 |

첫 요청 예시(가상 학생):

```
/생기부 2학년 정보 세특, 1,500Byte. 학생1. 블록 코딩 반복 단원.
정다각형을 반복 블록 하나로 그리는 방법을 스스로 찾음. 오각형 회전 각도를 108도로 넣어 실패했다가
외각을 다시 확인하고 72도로 고침. 모둠원에게 회전 각도 구하는 법을 예시를 만들어 설명함.
꽃 무늬 중첩 반복 과제에 도전함(완성 여부 모름).
```

## 3. AI의 질문에 답하기

AI는 바로 쓰지 않고 먼저 묻습니다. 한 번에 다섯 개 이하이고, 질문마다 왜 필요한지 한 줄이 붙습니다.

- **기본 질문**: 항목이 헷갈리면 항목, 세특이면 성취기준, 목표 분량.
- **심화 질문(한 번)**: 메모에서 개별성이 약한 자리 두세 곳. 예: "'열심히 했다'고 하셨는데, 그렇게 판단하신 장면이 있을까요?"
- 아는 것만 답하고 모르면 **"없음"** 또는 **"모름"**이라고 하시면 됩니다. AI는 없는 내용을 빼고 쓰거나 `[교사 확인 필요: ○○]`로 비워 둡니다.
- 질문 없이 바로 받고 싶으면 "묻지 말고 써"라고 하시면 됩니다. 이때 빈자리는 `[교사 확인 필요]`로 남습니다.

## 4. 초안이 나오기까지 — AI가 안에서 하는 일

초안을 쓴 뒤 AI가 스스로 AI 문체 점검을 한 번 합니다. 교사가 따로 시킬 필요는 없습니다.

1. **점수 매기기**: 스크립트가 "단순한 X를 넘어", "~로 이어짐", "탁월함", "~이 기대되는 학생임" 같은 AI 문체 틀을 셉니다.
2. **진단**: 틀이 여럿이면 하위 에이전트가 글을 처음 보는 눈으로 어떤 틀이 이 글을 지배하는지 고르고, 반드시 남길 낱말을 적습니다.
3. **윤문**: 그 틀만 걷어 냅니다. 수치, 핵심 낱말, '노력함 · ~하려고 · 도전함' 같은 표현은 그대로 둡니다. 노력이 성취로 바뀌면 과장 기재가 되기 때문입니다.
4. **복원 · 게이트**: 스크립트가 고친 글을 원래 글과 비교합니다. 너무 많이 고쳤는지, 수치나 핵심 낱말이 빠졌는지, 새 틀을 만들었는지 보고, 걸리면 되돌리거나 다시 고칩니다.
5. **기계 검사**: Byte, 금칙어(대회 · 수상 · 상호명 · 대학명 등), 한자 · 특수문자, 명사형 종결을 검사합니다.

### 분량이 모자라다고 할 때

AI 문체를 걷어 내면 글이 짧아집니다. 시험한 초안은 1,287Byte에서 877Byte로 줄었습니다. 목표의 90%에 못 미치면 AI는 문장을 늘려 채우지 않습니다. 그렇게 채운 문장이 바로 걷어 낸 틀이기 때문입니다. 대신 이렇게 묻습니다.

> 처음 초안에 '깊이 있는 탐구 태도'라고 썼는데, 그렇게 보신 장면이 있을까요?

장면을 알려 주시면 그 사실만 넣어 다시 씁니다. 없으면 "없음"이라고 하시면 분량이 모자란 채로 내고, 목표 대비 비율을 밝힙니다. 짧아도 사실만 있는 기록이 긴 과장 기록보다 낫습니다.

## 5. 초안 받기와 확인

결과는 이런 모양으로 나옵니다.

```
[초안 — 교사 확인 후 입력]
항목: 과목별 세부능력 및 특기사항 / 과목·영역: 정보 / 목표: 1,500Byte

(본문)

---
분량: 1,402Byte / 목표 1,500Byte (계산)
교사 확인 필요
- 사실: 관찰 메모를 넘어선 표현
- 과장: 평가어가 붙은 자리
- 항목 적합성: 다른 항목 내용이 섞였는지
- 비워 둔 자리: [교사 확인 필요] 목록
기재요령 점검: 금지 사항 해당 없음
```

입력 전에 교사가 할 일은 셋입니다.

1. **'교사 확인 필요' 목록을 하나씩 봅니다.** 특히 '사실' 줄 — 메모에 없던 표현이 들어왔는지 봅니다.
2. **`[교사 확인 필요: ○○]` 자리를 채우거나 지웁니다.** 그대로 나이스에 들어가면 안 됩니다.
3. **분량을 확인합니다.** '계산'이면 스크립트가 센 값이고, '추정'이면 `바이트 계산기.html`로 다시 셉니다.

기재요령 유의사항 4-다가 요구하는 것은 수정이 아니라 **최종 입력 전 확인**입니다. 위 셋을 마쳤다면 초안 문장이 그대로 들어가도 요건에 어긋나지 않습니다.

## 6. 여러 학생 한꺼번에

- `4. 교사 입력 양식`의 **E 양식**을 씁니다. 과목 · 성취기준 · 활동 같은 공통 정보는 한 번만 적고, 학생별로는 메모만 적습니다.
- **5~10명씩** 묶기를 권합니다. 너무 많이 묶으면 학생마다 들이는 주의가 흐려지고, 글의 뼈대가 서로 닮아 갑니다.
- 묶음이 끝나면 **새 대화**에서 다음 묶음을 시작합니다. 대화가 길어질수록 한 명당 비용이 커집니다.
- 여러 학생을 한꺼번에 검사하면 학생 사이에 같은 문장이 있는지도 함께 봅니다. 학생 간 기록이 같거나 뒤바뀐 것은 정정 사유입니다. 기호와 학생의 대응을 입력 전에 꼭 맞춰 봅니다.
- 분량이 모자란 학생은 따로 모아 한 번에 묻습니다.

## 7. 사용량 — 얼마나 쓸 수 있나

Claude Pro 요금제에서 직접 재 본 값을 바탕으로 한 **대략의 추정**입니다. 요금제 · 모델 · 글 길이에 따라 달라집니다.

| 진행 방식 | 학생 1명당 | 5시간 한도로 |
|---|---|---|
| 학생마다 새 대화 | 약 4.5~6% | 약 15~20명 |
| 한 대화에서 이어서 | 약 2~3% | 약 30~40명 |
| 한 번에 5~10명 묶어서 | 약 1~1.5% | 더 많이(주간 한도가 먼저 찰 수 있음) |

- 비용의 대부분은 지침을 읽고 하위 에이전트를 띄우는 고정 비용입니다. 묶어서 처리할수록 한 명당 비용이 줄어듭니다.
- 앱의 사용량 화면에서 시작 전과 끝난 뒤의 %를 보면 내 환경의 실제 값을 알 수 있습니다.

## 8. 자주 묻는 것

**스킬이 안 켜집니다.**
"생기부 써줘", "세특 초안"처럼 항목 이름이 들어간 말로 다시 부르십시오. Claude Code에서는 `/생기부`가 플러그인 설치 때만 있습니다. Gemini는 학교 · 교육청 Workspace 계정에서 스킬 기능이 막혀 있을 수 있습니다.

**검사 결과에 ERROR가 있습니다.**
ERROR는 나이스에 넣으면 안 되는 것입니다(분량 초과, 대회 · 수상 · 자격증 · 상호명 · 대학명, 한자, 수치 소실 등). AI가 고친 뒤 내지만, 남아 있으면 그 자리를 고쳐 달라고 하십시오. WARN은 확인할 거리이고, INFO는 참고입니다.

**'엔트리'가 상호명으로 걸립니다.**
교육용 프로그래밍 환경 이름이면 '블록 기반 프로그래밍 환경'으로 바꿉니다. '표의 엔트리'처럼 일반 낱말이면 무시하셔도 됩니다(그래서 ERROR가 아니라 WARN입니다).

**나이스 Byte와 다르게 나옵니다.**
스크립트는 한글 3Byte, 영문 · 숫자 · 공백 1Byte, 엔터 1Byte로 셉니다. 전각 기호와 가운뎃점은 3Byte로 보수적으로 셉니다. 학기를 나눠 입력하면 학년 단위 항목은 두 학기 합계가 상한입니다. 차이가 나면 소속 학교 나이스 값이 기준입니다.

**AI가 쓴 문장이 너무 짧고 밋밋합니다.**
의도된 결과입니다. 평가어와 연결어를 걷으면 사실만 남습니다. 길게 하려면 장면(학생이 한 일)을 더 알려 주십시오. 평가어를 다시 넣어 달라고 하면 과장 기재 위험이 커집니다.

**AI 문체 점검을 건너뛰고 싶습니다.**
"AI 문체 점검은 가볍게만 해 줘"라고 하면 진단 없이 최소한만 고칩니다. 아예 빼는 것은 권하지 않습니다. 걷어 내는 틀 대부분이 근거 없이 무게를 더하는 표현이라 과장 기재와 겹칩니다.

**지난 학생부 글로 기준을 맞추고 싶습니다.** (선택)
교사 PC 로컬 폴더에 지난 학생부 글 30편 이상을 `.txt`로 두고 아래 명령을 직접 돌리면, 사람이 쓴 학생부 글의 평균이 AI 문체 점수의 기준이 됩니다. 기준선 파일에는 숫자만 남고 글은 남지 않습니다. 학생 글을 AI 대화에 넣지 말고 명령은 직접 실행하십시오.

```
python "<스킬 폴더>/scripts/student_record_humanize.py" calibrate <로컬 폴더>
```

## 9. 하지 말 것

- 학생 글이 든 파일을 구글 드라이브 · OneDrive 같은 동기화 폴더에 두기
